# Code-Server 多用户登录系统改造文档

> 本文档汇总了对腾讯云服务器（`ubuntu@43.143.217.79`）上 code-server 的全部改造操作，
> 包括架构设计、文件清单、洛书（Losu）量子语言环境集成等。
> 部署目录：服务器上的 `/opt/codeserver-auth`。

---

## 一、改造目标

这次改造核心就是解决原版 code\-server 单用户、无隔离、样式简陋的问题，同时配齐洛书语言运行环境，具体目标如下：

1. **重构登录页面**：参考[ohmyppt\.cc](https://www.ohmyppt.cc) 的暖色纸感设计，换掉原生老旧登录界面，视觉更舒服、更有质感。
2. **实现双登录模式**
    - **普通用户登录**：不用手动注册，输入用户名密码即可自动注册；每个用户独立专属文件夹，用户账号密码信息用本地JSON文件存储，完全本地化。
    - **游客登录**：纯临时体验模式，全程不做任何数据持久化，退出后所有内容清空。
3. **统一容器化运行**：整套服务全部基于 Docker 容器部署，环境统一、方便迁移、开机自启，不用折腾服务器本地环境。
4. **深度集成洛书（Losu）量子语言环境**
    - 默认预装 `losu-2.0.0.vsix` 官方插件，打开编辑器直接可用。
    - 全局开放 lpk 仓库 quest 分支的 src 源码目录，所有用户均可查看学习。
    - 配置全局环境变量 `$LOSU_PATH`，适配脚本运行规则。
    - 部署 QLosu 官方解释器，服务器全局支持 losu 代码运行。

## 二、整体架构

原先的 code-server 用的是「单一密码」模式，无法支持多用户。改造后采用**网关（Gateway）+ 后端 code-server** 的双容器架构：

```
公网 :80
   │
   ▼
┌─────────────────────┐     内部网络 csnet      ┌──────────────────────┐
│   cs-gateway        │ ──────────────────────► │   cs-backend         │
│   (Node/Express)    │   http://code-server    │   (code-server)      │
│                     │        :8080            │                      │
│  · 唯一公网入口      │                         │  · auth=none         │
│  · 登录页/会话管理   │                         │  · 仅内部可达         │
│  · 反向代理 + WS     │                         │  · 内置 Python/Losu  │
└─────────────────────┘                         └──────────────────────┘
```

**设计要点：**

- **code-server 关闭自带认证**（`--auth none`），且**不暴露公网端口**，只能通过内部网络被网关访问。
- **网关是唯一公网入口**，负责：登录页、会话管理、把所有 HTTP + WebSocket 流量代理给 code-server。
- **凭据隔离**：用户密码、账号信息的JSON文件只挂载给网关容器，后端编辑器容器完全无法读取，从根源避免用户凭据泄露。

## 四、关键文件说明

### 4.1 `docker-compose.yml`

整个系统分为两个独立容器服务，分工明确，互不干扰：

| 服务 | 容器名 | 镜像 | 端口 | 说明 |
|------|--------|------|------|------|
| code-server | `cs-backend` | `code-server-python:latest`（本地构建） | 仅 `expose 8080`，不映射公网 | 后端编辑器 |
| gateway | `cs-gateway` | `node:24-alpine` | `80 -> 8080` | 公网入口 |

**目录挂载规则**

- **cs\-backend后端容器**
    - 用户工作区目录读写挂载，保证每个人的代码文件持久化保存
    - 洛书lpk源码目录**只读挂载**，防止共享源码被误改、篡改
- **cs\-gateway网关容器**
    - 挂载网关源码，支持热更新修改页面和逻辑
    - 独占用户凭据目录，保证账号数据安全隔离
    - 挂载工作区目录，用于新用户注册时自动创建专属文件夹

两个容器都设置了 `restart: unless-stopped`，**开机自启、异常自动重启**。

### 4.2 `.env`环境变量文件

```
PUBLIC_PORT=80
SESSION_SECRET=<随机生成的会话密钥>
```

> 说明：搭建时先用 `PUBLIC_PORT=8080` 测试端口验证，确认无误后切到 `80`，并保留了旧的独立 code-server 容器作为回退（已停止，未删除）。

### 4.3 `code-server/Dockerfile`

基于官方 `codercom/code-server:latest`，在其上叠加：

```dockerfile
FROM codercom/code-server:latest
USER root

# 1) 换腾讯云内网 Debian 源（默认 deb.debian.org 在该区域不可达会卡死），
#    安装 Python3 / pip / venv / git
RUN sed -i 's|http://deb.debian.org|http://mirrors.tencentyun.com|g' \
        /etc/apt/sources.list.d/debian.sources \
  && apt-get update \
  && apt-get install -y --no-install-recommends python3 python3-pip python3-venv git \
  && ln -sf /usr/bin/python3 /usr/local/bin/python \
  && apt-get clean && rm -rf /var/lib/apt/lists/*

# 2) 洛书解释器，同时提供 losu 和 QLosu 两个命令
COPY QLosu /usr/local/bin/QLosu
RUN chmod +x /usr/local/bin/QLosu \
  && ln -sf /usr/local/bin/QLosu /usr/local/bin/losu

# 3) 环境变量 $LOSU_PATH（同时写入 profile.d，登录/非登录 shell 都生效）
ENV LOSU_PATH=/home/coder/losu-lpk/src/script/example
RUN echo 'export LOSU_PATH=/home/coder/losu-lpk/src/script/example' \
        > /etc/profile.d/losu.sh && chmod +x /etc/profile.d/losu.sh

# 4) 预装洛书 VS Code 插件（装进 coder 默认扩展目录，所有用户共享）
COPY losu-2.0.0.vsix /tmp/losu-2.0.0.vsix
RUN HOME=/home/coder code-server --install-extension /tmp/losu-2.0.0.vsix \
  && rm -f /tmp/losu-2.0.0.vsix \
  && chown -R coder:coder /home/coder/.local

USER coder
```

> 构建产物镜像：`code-server-python:latest`（约 1.47 GB，含 Python 3.13）。

### 4.4 `gateway/server.js`（网关核心逻辑）

主要职责：

- **用户登录 / 自动注册**（`POST /_auth/login`）
  - 用户名规则：2–32 位小写字母、数字、`_`、`-`（防路径穿越）。
  - 不存在该用户 → 自动注册：用 `scrypt` 加盐哈希密码，写入 `data/auth/<用户名>.json`，并创建工作区文件夹。
  - 已存在 → 校验密码（`timingSafeEqual` 防时序攻击）。
- **游客登录**（`POST /_auth/guest`）
  - 在 `workspaces/.guests/` 下建临时文件夹，不写任何凭据文件。
  - 退出登录时删除该临时文件夹。
- **退出登录**（`GET /_auth/logout`）
- **鉴权门**：未登录访问页面 → 重定向到登录页；其它请求 → 401。
- **反向代理**：登录后所有 HTTP + WebSocket 流量转发给 code-server。
- **Losu 软链接**：每次登录在用户/游客工作区里创建 `losu-lpk-src` → `/home/coder/losu-lpk/src` 的软链接，方便在文件浏览器里查看洛书示例。

**用户凭据 JSON 示例**（`data/auth/<用户名>.json`）：

```json
{
  "username": "alice",
  "salt": "随机盐值",
  "hash": "scrypt 哈希后的密码",
  "workspace": "/home/coder/workspaces/alice",
  "createdAt": "2026-06-26T06:42:31.985Z",
  "lastLogin": "2026-06-26T06:42:32.090Z"
}
```

### 4.5 登录页（`gateway/public/`）

仿 ohmyppt.cc 暖色「纸感」风格：
- **配色**：主色棕 `#8b5e3c`、橙 `#e87d3e`、奶油底 `#f5e6c8` / `#fff8ea`。
- **元素**：浮动光晕背景、毛玻璃圆角卡片、`</>` Logo。
- **两个切换标签页**：「用户登录」「游客体验」。

## 五、本次会话的操作时间线

按实际执行顺序记录的关键操作：

### 阶段一：登录系统改造
1. SSH 连入服务器，发现已有一个 `codercom/code-server:latest` 容器（单密码模式，端口 80）。
2. 分析 code-server 内部登录模板与认证逻辑。
3. 抓取 ohmyppt.cc 的 CSS，提取暖色配色方案。
4. 设计「网关 + 后端」双容器架构（用户选择了**共享进程 + 文件夹路由**方案，省内存）。
5. 本地编写全部文件：`docker-compose.yml`、网关代码、登录页。
6. 先在测试端口 `8090` 部署验证（用户选择**先测试端口再切换**）。
7. 验证通过后切到端口 `80`，停止（保留）旧容器作为回退。

### 阶段二：修复 WebSocket 1006 报错
- **现象**：进入编辑器后报 `WebSocket close with status code 1006`。
- **根因**：代理设了 `changeOrigin: true`，把 `Host` 头改写成了 `code-server:8080`，与浏览器的 `Origin`（`43.143.217.79`）不匹配，被 code-server 的 CSRF 校验拒绝。
- **修复**：改为 `changeOrigin: false`，保持 Host 与 Origin 一致。验证：匹配 Origin → `101 Switching Protocols`；伪造 Origin → `403`。

### 阶段三：终端缺少 Python
- **现象**：终端里没有 Python3。
- **修复**：用 Dockerfile 把 `python3 / pip / venv` 装进镜像（持久化，不会因重建丢失）。
- **插曲**：首次构建因默认 Debian 源不可达卡了 10 分钟 → 换成腾讯云内网源 `mirrors.tencentyun.com`，构建缩短到约 12 秒。最终 Python 3.13.5。

### 阶段四：集成洛书（Losu）量子语言
1. 把本机 `QLosu` 解释器、`losu-2.0.0.vsix` 上传到服务器构建上下文。
2. 克隆 lpk 仓库 `quest` 分支到 `data/losu-lpk`，只读挂载给后端。
3. Dockerfile 中：装解释器（`losu`/`QLosu`）、设 `$LOSU_PATH`、预装插件。
4. 网关每次登录给工作区建 `losu-lpk-src` 软链接。
5. 验证：`losu test.losu` 正常输出量子态结果；`$LOSU_PATH` 在登录/非登录 shell 均生效；插件已安装；软链接正确解析。

## 七、运维常用命令

> 以下命令均在服务器上执行（先 `ssh ubuntu@43.143.217.79`）。

**查看容器状态：**
```bash
cd /opt/codeserver-auth && sudo docker compose ps
```

**查看日志：**
```bash
sudo docker compose logs gateway      # 网关日志
sudo docker compose logs code-server  # 后端日志
```

**重启服务：**
```bash
sudo docker compose restart gateway       # 改了 server.js / 登录页后
```

## 八、运行洛书程序的正确姿势

`QLosu`/`losu` 解释器**只认你给的文件路径**，不会自动去 `$LOSU_PATH` 搜索。
若直接在工作区敲 `QLosu test.losu` 而当前目录没有该文件，就会找不到、不编译。

正确做法（任选其一）：

```bash
# 方式一：用环境变量拼完整路径
QLosu $LOSU_PATH/test.losu

# 方式二：先进入示例目录
cd $LOSU_PATH && QLosu test.losu

# 方式三：通过工作区里的软链接
QLosu losu-lpk-src/script/example/test.losu
```

> 备注：如果希望「在任意目录直接 `QLosu test.losu` 就能跑」，可以给解释器包一层
> 脚本，让它先找当前目录、找不到再去 `$LOSU_PATH` 搜索。目前尚未启用此功能。

## 九、现存问题与后续待优化

- **隔离强度**：当前是「共享进程 + 文件夹路由」方案。登录隔离已生效、密码哈希在编辑器内不可读；但同一进程下，用户理论上可在文件系统中浏览到 `/home/coder/workspaces` 下他人的目录。若需硬隔离，可升级为「每用户独立进程」方案。
- **lpk 只读**：仓库以只读方式挂载，用户能读/运行示例但不能改动共享副本（可复制到自己工作区后编辑）。如需每人独立可写副本，可改造。
- **HTTPS**：当前为 HTTP（端口 80）。如需加密可配置 HTTPS。
- **旧容器**：原 `code-server` 独立容器已停止但未删除，作为回退保留。
- **游客清理**：游客文件夹在退出登录时删除；若会话过期未主动退出，可加定时清理任务。

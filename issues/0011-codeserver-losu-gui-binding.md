# 0011 Code-Server GUI 与洛书工作台绑定

- **优先级：** P1
- **状态：** 浏览器与 Linux Electron 工作台加载、运行、终端已验收
- **范围：** `apps/code-server/`、`extensions/qlosu-vscode/`、`electron/`、工作台配置
- **依赖：** 0002、0008、0009

## 背景

当前主界面由 Code-Server 提供完整的 VS Code Workbench，洛书能力主要通过扩展活动栏、命令和 Webview 提供。用户首次打开时仍能看到大量通用 VS Code 入口，品牌、默认布局和洛书工作流之间的关系不够清晰。

本 issue 的目标是把 Code-Server 绑定为洛书 IDE 的工作台：保留编辑器、终端、资源管理器、设置和扩展机制等必要能力，同时减少不属于洛书主流程的视觉入口和默认配置。绑定应通过扩展、用户配置和启动参数完成，避免修改 Code-Server 核心源码，确保后续可以升级固定版本。

## 待完成

- 建立统一的洛书产品标题、Logo、欢迎页和窗口图标，覆盖浏览器页签、Electron 窗口和工作台品牌区域。
- 提供洛书默认工作台布局：资源管理器、洛书活动栏、编辑器、终端、问题/输出面板和图表标签页的初始位置明确。
- 将运行洛书、选择运行时、打开语法手册、量子线路和程序流程图作为首要命令入口，并为 `.losu` 文件提供上下文操作。
- 通过可恢复的配置隐藏或弱化与洛书无关的默认入口、推荐扩展、欢迎内容和遥测提示；不能破坏用户重新启用标准 VS Code 功能的能力。
- 配置 Code-Server 启动时自动打开指定工作区和洛书欢迎视图，浏览器刷新、窗口重开和无工作区启动时行为一致。
- 统一浅色/深色主题中的洛书色彩、图标和状态提示，避免旧 GUI、Code-Server 和扩展出现不同品牌。
- 增加设置项或启动参数切换“洛书工作台模式”和“标准 VS Code 模式”，便于调试、升级和高级用户恢复完整界面。
- 为布局、品牌资源、命令入口和模式切换增加无图形环境的配置测试，以及至少一次 Code-Server 实际工作台验收。

## 验收标准

- 首次启动 Code-Server 后，用户进入洛书工作区并能直接看到洛书入口，不需要手动寻找扩展命令。
- 默认界面不展示重复的旧 Web IDE 入口，洛书功能在活动栏、命令面板和编辑器上下文菜单中命名一致。
- 终端、资源管理器、设置、扩展管理和标准编辑能力仍可通过“标准 VS Code 模式”恢复。
- 浏览器和 Electron 使用同一套品牌资源、默认布局和模式配置。
- 不修改 Code-Server 核心源码；升级 Code-Server 固定版本后，绑定层可独立重新打包和回归验证。
- 验收记录包含工作区启动、布局加载、模式切换、`.losu` 命令入口和品牌资源加载结果。

## 实施边界

- 优先使用 VS Code/Code-Server 支持的产品配置、扩展 API、命令、context key、欢迎视图和用户设置。
- 只有在扩展 API 无法实现时，才评估补丁或构建层修改；任何此类修改必须记录版本差异和升级回退方案。
- “减少 VS Code 特征”指默认呈现和品牌体验收敛到洛书，不删除编辑器内核、终端、文件操作、扩展 API 或用户可恢复的标准能力。

## 本次完成

- Code-Server 启动管理器新增洛书工作台配置注入：只补齐缺失设置，不覆盖已有用户配置。
- 默认设置包括洛书窗口标题、无默认欢迎页、关闭提示/推荐扩展、关闭遥测和启用 `qlosu.workbenchMode`。
- 扩展新增 `QLosu: Toggle Losu Workbench Mode` 命令，可在洛书工作台和标准 VS Code 工作台之间切换。
- 增加无图形配置回归测试，验证用户设置保留及重复启动幂等；`npm run smoke:local` 已验证工作区、终端、流程图和 Code-Server 进程清理。
- 浏览器模式实测 Code-Server 工作台根地址和带 `?folder=` 的工作区地址均返回 HTTP 200；冒烟测试现在会断言洛书窗口标题、工作台模式和遥测设置已写入用户配置。
- 发现并修复 Fedora 当前 Node ABI 下 Code-Server 缺少 `@vscode/spdlog` 原生绑定导致的 404；构建脚本现在会自动重建该依赖。
- 桌面启动器统一复用 Code-Server 工作区参数和洛书品牌窗口图标；`desktop:check` 可在无图形环境验证 Electron 安装状态，主进程在工作台崩溃时回退兼容页面并提示用户。
